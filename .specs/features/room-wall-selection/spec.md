# Room Wall Selection Specification

## Problem Statement

Users need a Unity iOS app that displays a 3D room and lets them select walls by tapping, with clear visual feedback and a real-time list of wall states. The app also supports cutting window holes into walls, an AR-driven camera mode, and an interactive 2D top-down plan. This is the core deliverable of the Unity_IOS_mini_task project.

## Goals

- [ ] User can view a synthetic 3D room from a first-person camera and orbit it via touch drag
- [ ] User can toggle wall selection by tapping, with outline + tint feedback, mirrored in a real-time list
- [ ] User can clear the whole selection via button or by tapping empty space
- [ ] User can cut rectangular window holes into walls by dragging two corners (real mesh cut)
- [ ] User can switch to an AR mode where device pose drives the camera, and to an interactive 2D top-down plan

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
| ------- | ------ |
| Real-wall detection via LiDAR/ARKit plane detection | User decision: synthetic room is the room source; AR extra only drives the camera pose |
| iOS device build validation | User decision: validation target is the Unity Editor only; project stays iOS-exportable but no device build is required |
| Camera zoom (pinch) | User decision: first-person orbital camera without zoom |
| Window hole editing/deletion after placement | Not in ideia.md; placement only. Deferred idea |
| Persistence of selection/windows between sessions | Not in ideia.md; runtime state only |
| Multi-room support | Single room per ideia.md |

## User Stories

### P1: Orbit a synthetic room ⭐ MVP

**User Story**: As a user, I want to see a 3D room and look around it by dragging my finger so that I can view every wall.

**Why P1**: Without the room and camera nothing else is usable.

**Acceptance Criteria** (each line is one EARS pattern):

1. The system SHALL render a synthetic rectangular room with 4 walls, floor and ceiling, generated by code that supports any number N >= 3 of walls. <!-- ubiquitous -->
2. WHEN the user drags one finger horizontally THEN the system SHALL rotate the first-person camera yaw proportionally to the drag, with full 360 deg freedom. <!-- event-driven -->
3. WHEN the user drags one finger vertically THEN the system SHALL rotate the camera pitch proportionally to the drag, clamped to the configured pitch range (-60 deg to +60 deg default). <!-- event-driven -->
4. The system SHALL keep the camera positioned inside the room (first-person viewpoint) at all times. <!-- ubiquitous -->
5. WHILE running in the Unity Editor the system SHALL accept mouse drag as the touch-drag equivalent. <!-- state-driven -->

**Independent Test**: Open the scene in Play Mode, drag with mouse; camera orbits 360 deg horizontally and clamps vertically; all 4 walls become visible by orbiting.

---

### P1: Select walls by tapping ⭐ MVP

**User Story**: As a user, I want to tap a wall to toggle its selection with clear visual feedback so that I always know which walls are selected.

**Why P1**: Wall selection is the core interaction of the app.

**Acceptance Criteria**:

1. WHEN the user taps a wall that is not selected THEN the system SHALL mark it selected and display an outline plus a tint on that wall. <!-- event-driven -->
2. WHEN the user taps a wall that is selected THEN the system SHALL mark it not selected and remove its outline and tint. <!-- event-driven -->
3. IF a touch moves more than the tap threshold or lasts longer than the tap duration THEN the system SHALL treat it as a camera drag and SHALL NOT change any wall's selection state. <!-- unwanted-behavior -->
4. WHILE a wall is selected the system SHALL keep its outline and tint visible from any camera angle. <!-- state-driven -->
5. IF a tap hits the floor or ceiling THEN the system SHALL NOT change any wall's selection state. <!-- unwanted-behavior -->

**Independent Test**: Tap each wall once (selected, outlined+tinted), tap again (deselected); drag over a wall does not toggle it.

---

### P1: Real-time wall list ⭐ MVP

**User Story**: As a user, I want an on-screen list of every wall and its selection state so that I can audit the selection without orbiting.

**Why P1**: Explicit requirement in ideia.md; the list is the app's state readout.

**Acceptance Criteria**:

1. The system SHALL display a collapsible panel listing every wall by name with its current selection state. <!-- ubiquitous -->
2. WHEN any wall's selection state changes THEN the system SHALL update that wall's row in the list within the same frame. <!-- event-driven -->
3. WHEN the user taps the panel's collapse control THEN the system SHALL toggle the panel between expanded and collapsed. <!-- event-driven -->
4. WHILE the panel is collapsed the system SHALL keep the collapse control visible so the panel can be re-expanded. <!-- state-driven -->

**Independent Test**: Select/deselect walls while watching the panel; rows flip state instantly; panel collapses and expands.

---

### P1: Clear selection ⭐ MVP

**User Story**: As a user, I want to clear the whole selection with one action so that I can restart quickly.

**Why P1**: Explicit requirement; user chose button AND tap-outside.

**Acceptance Criteria**:

1. WHEN the user taps the Clear button THEN the system SHALL set every wall to not selected. <!-- event-driven -->
2. WHEN the user taps empty space (no wall, floor, ceiling or UI hit) THEN the system SHALL set every wall to not selected. <!-- event-driven -->
3. WHEN the selection is cleared THEN the system SHALL remove all outlines and tints and update every list row. <!-- event-driven -->
4. IF the selection is already empty THEN the system SHALL leave all state unchanged when Clear is triggered. <!-- unwanted-behavior -->

**Independent Test**: Select 2 walls, press Clear (all deselect); select again, tap the sky/empty area (all deselect).

---

### P2: Window holes by rectangle drag

**User Story**: As a user, I want to draw a rectangle on a wall to cut a real window hole so that I can plan window placement.

**Why P2**: Listed in ideia.md as a feature beyond the core selection loop; independent of P1 flow.

**Acceptance Criteria**:

1. WHEN the user activates window mode via its toggle button THEN the system SHALL route wall drags to window drawing instead of camera orbit. <!-- event-driven -->
2. WHILE the user drags on a wall in window mode the system SHALL display a real-time rectangle preview between the drag start corner and the current finger position, projected onto that wall. <!-- state-driven -->
3. WHEN the user releases a valid drag THEN the system SHALL cut a rectangular hole through the wall mesh so the outside is visible through it. <!-- event-driven -->
4. The system SHALL clamp the rectangle so it lies fully inside the wall's bounds. <!-- ubiquitous -->
5. IF the released rectangle overlaps an existing window on the same wall THEN the system SHALL reject the placement and remove the preview without modifying the wall. <!-- unwanted-behavior -->
6. IF the released rectangle is smaller than the minimum window size THEN the system SHALL reject the placement and remove the preview without modifying the wall. <!-- unwanted-behavior -->
7. The system SHALL support multiple non-overlapping windows per wall. <!-- ubiquitous -->
8. IF a drag in window mode starts on empty space, floor or ceiling THEN the system SHALL NOT create a preview or a window. <!-- unwanted-behavior -->

**Independent Test**: Enter window mode, drag on a wall (preview follows finger), release (see through the hole); attempt overlapping and tiny rectangles (both rejected).

---

### P3: AR pose camera mode

**User Story**: As a user, I want to look around the synthetic room by moving my iPhone so that camera control feels natural.

**Why P3**: Marked "Extra" in ideia.md; replaces touch orbit, does not add new room capability.

**Acceptance Criteria**:

1. WHEN the user enables AR mode THEN the system SHALL drive the room camera's rotation and position from the device's AR pose (AR Foundation device tracking). <!-- event-driven -->
2. WHILE AR mode is active the system SHALL ignore touch-drag camera input. <!-- state-driven -->
3. WHEN the user disables AR mode THEN the system SHALL restore touch-drag orbital control from the current camera orientation. <!-- event-driven -->
4. WHERE AR tracking is unavailable on the running platform the system SHALL keep the AR mode toggle disabled with the touch camera as fallback. <!-- optional-feature -->
5. WHILE AR mode is active the system SHALL keep wall tap selection functional. <!-- state-driven -->

**Independent Test**: With XR Simulation in Editor (or a device), enable AR mode; moving the simulated device rotates the room view; tapping walls still toggles selection.

---

### P3: Interactive 2D top-down plan

**User Story**: As a user, I want a top-down 2D plan of the room where I can also toggle walls so that I get an overview of the project.

**Why P3**: Marked "Extra" in ideia.md.

**Acceptance Criteria**:

1. WHEN the user taps the plan toggle button THEN the system SHALL switch to an orthographic top-down view of the room. <!-- event-driven -->
2. WHILE the top-down view is active the system SHALL render selected walls with the same tint state as the 3D view. <!-- state-driven -->
3. WHEN the user taps a wall in the top-down view THEN the system SHALL toggle that wall's selection state, mirrored in the 3D view and the list. <!-- event-driven -->
4. WHEN the user taps the plan toggle again THEN the system SHALL return to the previous 3D camera view. <!-- event-driven -->
5. WHILE the top-down view is active the system SHALL keep the wall list panel and Clear button functional. <!-- state-driven -->

**Independent Test**: Toggle to plan, see selected walls highlighted; tap a wall in the plan (list updates); toggle back to 3D (selection consistent).

## Edge Cases

- IF two touches land in the same frame THEN the system SHALL process only the primary touch for tap/drag logic. <!-- unwanted-behavior -->
- IF a tap hits a UI element (panel, buttons) THEN the system SHALL NOT raycast into the 3D scene. <!-- unwanted-behavior -->
- WHEN a window drag releases with the finger off the original wall THEN the system SHALL clamp the end corner to that wall's bounds instead of switching walls. <!-- event-driven -->
- IF window mode is active and the user taps a wall without dragging THEN the system SHALL NOT create a window (below minimum size rule applies). <!-- unwanted-behavior -->
- IF the wall mesh rebuild fails validation (degenerate geometry) THEN the system SHALL keep the previous wall mesh and reject the window. <!-- unwanted-behavior -->
- WHEN the selection changes while the list panel is collapsed THEN the system SHALL still update the underlying rows so the panel is correct when expanded. <!-- event-driven -->

## Success Criteria

How we know the feature is successful:

- [ ] All 4 walls can be viewed, selected and deselected in under 30 seconds of first use, with the list always matching the 3D state
- [ ] Zero false selections: 20 consecutive orbit drags over walls produce no selection toggles
- [ ] A window hole shows the outside through the wall, and invalid rectangles (overlap, too small) are always rejected
- [ ] EditMode + PlayMode test suites pass for selection logic, window validation, mesh cutting and tap interaction
